# Repolis v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Vercel-hosted web app where any public GitHub repo becomes a holographic 3D city that replays its history, can be flown through, and has a shareable link per repo.

**Architecture:** A Next.js App Router app. Three server route handlers turn GitHub history into JSON:
- **latest city:** today's files;
- **manifest:** up to 200 snapshot commits;
- **batches:** per-snapshot file changes.

Results are cached in Vercel's managed Data Cache (`unstable_cache`) and CDN; there's no database. The browser:
1. shows today's city first;
2. streams history batches;
3. builds a deterministic city model (districts, layout, history) in pure TypeScript;
4. renders it with plain three.js, ported from the approved prototype.

**Tech Stack:** Next.js 16.4.3, React 19, TypeScript (the version `create-next-app@16.4.3` installs), three ^0.186.1, idb-keyval ^6.3.0, Vitest ^4.1.12 + @vitest/coverage-v8 ^4.1.12 + @vitejs/plugin-react ^5.2.0 + jsdom + Testing Library + fake-indexeddb, Playwright ^1.64.1.

**Spec:** [docs/superpowers/specs/2026-10-26-repolis-design.md](../specs/2026-10-26-repolis-design.md). The visual reference is [assets/2026-10-26-repolis-look-prototype.html](../specs/assets/2026-10-26-repolis-look-prototype.html), cited below as **proto L<n>**.

**Branch:** do all work on `feat/repolis-v1` (create it from `main` before Task 1).

## Global Constraints

### Snapshots and history
- `MAX_SNAPSHOTS = 200`, spread evenly **by commit index**, with the first and latest commit always included. Repos with ≤ 200 commits get one snapshot per commit (`exact = true`).
- Coarse mode (truncated GitHub trees): `COARSE_SNAPSHOTS = 30`.
- Huge repos: merge into ≤ `MAX_BUILDINGS = 20000` buildings.

### Timing and thresholds
- Replay autoplay: `REPLAY_SECONDS = 12` for all snapshots.
- Construction wave: `CONSTRUCTION_SECONDS = 5`. A snapshot triggers it when its added bytes exceed `CONSTRUCTION_SHARE = 0.3` of the final city's total bytes.
- District split threshold: `DISTRICT_SPLIT_SHARE = 0.35`. Root-level files go in district `"/"`.
- Today's city must appear within ~2 s on a first visit. Cached repos skip it: if history is ready within `FAST_PATH_MS = 1500` of page start, go straight to the replay.

### Exact copy

| Situation | Text |
|---|---|
| Invalid link | `Not a GitHub repo link` |
| Not found | `Repo not found or private` |
| Empty repo | `This repo is empty` |
| Rate limited | `GitHub is busy — try again in N minutes` |
| No WebGL | `Your browser can't show 3D` |
| Network failure (my call) | `Couldn't reach GitHub — try again` |
| One-commit repo | `Pushed all at once · 1 commit · 12 Mar 2024` (date as `D Mon YYYY`, en-GB) |
| History loading | `Fetching history… 63%` |

### Data and hosting
- No database, KV or Blob writes. Use only `unstable_cache` (Vercel Data Cache) and CDN `Cache-Control`. Keep data access in `src/lib/data/`.
- `GITHUB_TOKEN` exists only server-side (`process.env`). It is never sent to the client, logged or committed. `.env*` is already gitignored.
- Public repos only, and no sign-in.
- Server responses stay < 4.5 MB. Route `maxDuration = 60`.

### Look
- Look **B · Solid light** only: proto `STYLES['solid-light']` (proto L143), lights proto L387–401, bloom `(0.5, 0.4, 0.85)`, ACES tone mapping at exposure 1.0.
- Fonts: Space Grotesk (500/700, display) and JetBrains Mono (400/600, UI).

### Motion and performance
- Reduced motion: no fly-in, no autoplay. Show the final snapshot, paused.
- Targets: ~60 fps with ~5k buildings on a mid-range laptop, and ≥ 30 fps on a mid-range phone.

### Code standards
- TDD for every task, ≥ 80% coverage on lines/functions/branches/statements over the coverage include set, and unit + integration + E2E tests.
- Conventional commits.
- No `console.log`. `console.error` is allowed only in server error paths.
- Files stay focused (< 400 lines).

## Review Focus

These are inputs the spec implies but no feature test exercises. Each line names the task that owns the pinning test.

1. **Giant single files** (`package-lock.json`, binaries over 1 MB). Height caps at `0.2 + MAX_TOWER`, so one file can't dwarf the city. (Task 9)
2. **Link variants:** `.git` suffix, trailing slash, `www.`, `/tree/main/...`, SSH `git@github.com:o/r.git`, dots in names (`vercel/next.js`), mixed case. All parse to the right owner/repo. (Task 2)
3. **GitHub rate limit hit partway through history.** Today's city stays on screen, and the timeline shows the busy message with minutes. There's no full-page error. (Tasks 10, 13)
4. **Submodules (`type: "commit"`) and unicode/space paths in trees.** Submodules are ignored, and unicode paths are preserved byte-exact. (Task 4)
5. **Renamed repos or wrong case** (`/Facebook/React`). The page replaces the URL with GitHub's canonical `fullName`, and cache keys are lower-cased, so caches aren't duplicated. (Tasks 6, 13)

- Produces:
```ts
export interface CommitInfo { sha: string; treeSha: string; date: string; author: string | null; message: string }
export interface TreeEntry { path: string; type: 'blob' | 'tree' | 'commit'; sha: string; size?: number }
export interface RepoHead { fullName: string; defaultBranch: string; head: CommitInfo; totalCommits: number }
export interface GitHub {
  getRepoHead(ref: RepoRef): Promise<RepoHead>;
  getCommitCount(ref: RepoRef, sha: string): Promise<number>;
  getCommitsAtRanks(ref: RepoRef, headSha: string, ranks: number[]): Promise<CommitInfo[]>; // rank 0 = head; same order as ranks
  getTree(ref: RepoRef, treeSha: string, recursive: boolean): Promise<{ entries: TreeEntry[]; truncated: boolean }>;
  remaining(resource: 'core' | 'graphql'): { remaining: number; resetAt: number } | null;
}
export function createGitHub(opts: { token: string; fetch?: typeof fetch; now?: () => number }): GitHub;
export function getFullTree(gh: GitHub, ref: RepoRef, treeSha: string, maxDepth?: number): Promise<{ tree: TreeSnapshot; requests: number; truncated: boolean }>;
```

**GraphQL** goes to `POST https://api.github.com/graphql`. Every request sends `Authorization: Bearer <token>`, `User-Agent: repolis`, and `X-GitHub-Api-Version: 2022-11-28`.
- `getRepoHead`: `repository(owner,name){ nameWithOwner defaultBranchRef { name target { ... on Commit { oid committedDate messageHeadline tree { oid } author { name user { login } } history(first: 0) { totalCount } } } } }`.
- `getCommitCount`: `repository(...){ object(oid: $sha) { ... on Commit { history(first: 0) { totalCount } } } }`.
- `getCommitsAtRanks`: one aliased connection per rank inside `object(oid: $sha) { ... on Commit { ... } }`.
  - Rank 0 is `r0: history(first: 1) { nodes { ...C } }`.
  - Rank r ≥ 1 is `rN: history(first: 1, after: "<headSha> <r-1>") { nodes { ...C } }`.
  - Use at most 50 aliases per request.
  - If GraphQL returns errors that aren't NOT_FOUND or RATE_LIMITED, fall back to REST `GET /repos/{o}/{r}/commits?sha={head}&per_page=1&page={r+1}`, via `mapLimit` with a limit of 6.
- Map the author as `user.login ?? name ?? null`, and the message as the first line only.

**REST trees:** `GET /repos/{o}/{r}/git/trees/{sha}` with `?recursive=1` when recursive.

**Interfaces:**
- Consumes: `getFullTree` (`truncated`, `requests`), the Task 3 types (`MergePlan` already exists).
- Produces:
  - `MAX_BUILDINGS = 20000`, `KEEP_PER_FOLDER = 8`, `GITHUB_RESERVE = 300`
  - `planMerge(files: Array<[string, number]>, max?: number, keep?: number): MergePlan`. Folders are taken by file count, largest first. Each keeps its `keep` largest files and merges the rest, until the building count is ≤ max. `count` is the folder's merged-file count at head.
  - `mergedPath(path: string, plan: MergePlan): string`. Returns `path` itself, or `` `${folder}/+small` `` when it's under a planned folder and not in `keep`.
  - `applyMerge(tree: TreeSnapshot, plan: MergePlan): TreeSnapshot`. Sizes are summed. The sha is the sha1 of the sorted member shas joined with `,`, using `node:crypto`.
  - `ensureBudget(gh: GitHub, cost: number): void`. Throws `CityError('rate-limited', { retryAfterMinutes })` when `remaining('core').remaining - cost < 300`.
  - `buildLatest`, `buildManifest` and `buildBatch` accept an optional `opts: { maxBuildings?: number }`, for tests.
    - If the head tree is truncated: `mode: 'coarse'`, snapshots from `pickSnapshotIndices(total, COARSE_SNAPSHOTS)`, `batchSize: COARSE_BATCH_SIZE`.
    - If the head has more than `maxBuildings` files, `mergePlan = planMerge(head)`, and every tree is `applyMerge`d before diffing.
    - `buildBatch` calls `ensureBudget(gh, (batchSize + 1) * manifest.treeRequests)` first.
  - `buildTooltipInfo` for a `+small` path: title `"{folder} · +{count} small files"`.
